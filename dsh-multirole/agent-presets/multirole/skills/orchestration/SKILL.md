# 多角色协作模式 · 流转协议

本 skill 是总控的作业规程。模板文件（与本文件同目录）：
`任务单模板.md`、`授权书模板.md`、`裁决日志模板.md`——使用时原样复制到项目目录再填写。

## 第 0 条铁律 · 人的最小化

**本项目核心目标：人只干人必须干的事，其他一切都由机完成。**

- 凡是机端能做的事（列链接、翻文件、跑命令、复算、比对、归档），
  **一律禁止下推给人**。
- 交付给人的一律是「裁决包」：结论 + 机判/验证报告 + 签字点 +
  **所有引用文件的绝对路径链接**，人只做一分钟判断。
- 凡需要人自己开文件夹找文件才能判断的交付物，总控重写后再送。
- 此条优先级高于本协议其余一切条款；与之冲突的条款以此条为准。

## 第 1 条铁律 · 顾问信息充分

**召集顾问时，必须保证顾问获得作出高质量裁决所需的全部信息。**

- 任务单/召集文本中必须列出**所有关键输入文件的绝对路径**（协议、设计文档、事故记录、相关代码），明确要求顾问开工前自证已读。
- 涉及既有协议条款时，必须引用**原文**而非转述；禁止只给结论不给依据。
- 涉及外部项目经验时，必须给出**可核验的原始路径**，禁止凭记忆转述。
- 顾问声明「已核对/已通读」时，总控仍须抽查关键条款，防止顾问基于错误假设设计。
- 此条与第 0 条铁律同优先级；违反此条导致的顾问误判，责任在总控。

## 角色与边界

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| 人 | 总裁决：签字、叫停、质疑、授权；机端无法运行的活（登录态、付费） | 机械执行 |
| 顾问 | 总设计、参与决策、规格终审、授权 scope 内裁决 | 写代码、跑命令、改文件 |
| 总控 | 标准起草、落地方案、任务分派、验收、维护任务单体系 | 亲自执行重活、写业务代码 |
| 执行者 | 按任务单批量执行 | 设计决策、最终验收、向下派发 |

## 任务单制度（唯一事实源）

1. 一切派发落盘：项目目录下 `任务单/TASK-YYYYMMDD-NN.md`，格式照 `任务单模板.md`。
   禁止口头派活；任务单必须完全自包含，跨会话失忆时它是唯一事实源。
2. 必填字段：状态 / 执行者 / 会话策略 / 写入域 / 目标 / 输入 / 产出物 / 验收标准；
   批量任务加填断点幂等要求。验收标准必须可执行、可观测，禁止"跑通就行"。
3. 维护 `任务单/INDEX.md` 索引：状态流转 待派 → 进行中 → 待验收 → 完成 / 打回；
   索引带「写入域」列，一眼可查谁在占用什么。
4. 派发文本一律绝对路径锚定项目根；执行者开工 pwd 自证、交付 ls 自证。

## 并行铁律

所有「进行中」任务的写入域两两不相交。派发前逐对核对；相交则串行排队或重划边界。
只读共享不受限。产出物默认写任务专属目录，天然隔离。

## 会话策略

- 默认新会话（无状态任务，用完即弃）；任务单自包含是新会话的前提。
- 需要迭代反馈、上下文累积时才沿用会话（任务单注明会话编号）；
  上下文明显退化时归档旧会话、开新会话并重写自包含任务单。

## 验收闭环

1. 执行者交付（产出清单 + 验证输出 + 遗留问题）→ 总控亲验：亲自跑验证命令、
   复算关键数字，禁止凭自述通过。
2. 合格 → INDEX 回填「实际结果」、状态完成；不合格 → 打回并写明打回理由。
3. 交付给人的一律是裁决包：结论 + 机判/验证报告 + 签字点，人只做一分钟判断。
4. 生成类产出无 prompt 全文存档 = 未交付，验收一律不通过。

## 授权模式

### 标准模式（默认）
方向性决策、规格批准、验收终审一律报人；顾问只有建议权。

### 全授权模式
生效依据只有一种：项目目录内存在人签署的 `授权书`（格式照 `授权书模板.md`），
且在有效期内。口头声明无效。

- scope 内事项：顾问裁决（落盘 `logs/裁决日志.md`，格式照 `裁决日志模板.md`），
  总控按书面裁决执行。无落盘的裁决视为未发生。
- reserved 清单（授权书内列明；以下为内置默认，授权书可加项不可减项）：
  1. 消耗人专属资源（账号登录态、付费确认、对外发送/发布）；
  2. 不可逆操作（删除非产出物、推送远端、覆盖无备份文件）；
  3. 变更本模式自身（preset、本协议、授权书）；
  4. 叫停权本身。
- 命中 reserved 或授权预算（章数/天数/token 上限）触顶 → 立即停机，
  生成裁决包等人，禁止找顾问代行。
- 人一句话叫停即时生效，不设前提、无需顾问转发。
- 自动降级条款：顾问裁决引发的同类事故满两次（记入裁决日志），
  该决策类别自动从 scope 移回 reserved，总控负责执行此降级并报告人。

## 模型纪律

召集顾问/派发执行者时的 provider/model 选择：
1. 优先按人在授权书或任务单中的书面指定；
2. 未指定的，在 subagent 模型白名单（Web 设置 → 插件 → Subagent Model Selection）
   可用项中选，并在任务单备注所选路由；
3. 白名单为空或无合适项 → 报告人并请求指定，禁止擅自选择。

## 发布与回滚

发布走三闸口，三闸全过才允许正式版本发布；任一闸不过即打回，禁止带缺口发布。

### 三闸口判定规则
1. **版本合规 + 冒烟通过**：`dsh-multirole/package.json` 的 `version` 不带 `-dev`/`-rc` 后缀，且大于部署位 `.installed-version` 记录的版本；冒烟通过（S1 文档级 / S2 组合级）。
   - `-dev`/`-rc` 后缀机判：`scripts/install.sh` 内置 G1 闸口，命中即 FATAL 退出；
   - “大于部署位版本”与 S1/S2 冒烟证据：由总控在裁决包中列明证据，人确认后过闸。
2. **CHANGELOG 已更新**：`docs/CHANGELOG.md` 已有本版本条目（变更 + 冒烟两小节），非空。
3. **人点头**：标准模式 = 人本次点头；全授权模式 = 授权书豁免 + 首次确认。

### 备份 / 回滚
- 备份位置与保留策略（最近 3 份、首次 unknown 标记）、回滚步骤（选备份 → 执行 → S1 冒烟 → CHANGELOG 补录）、热修复纪律、沙箱规格（`--target dev`）：一律按 `docs/发布与回滚规程.md` 执行。
- `scripts/install.sh` 正式安装在覆盖部署位前自动备份（`<dshHome>\backups\multirole\<旧version>-<YYYYMMDD-HHMMSS>\`，`dshHome` 默认 `~/.dsh`（Linux/macOS）或 `%USERPROFILE%\.dsh`（Windows），可用 `DSH_HOME` 覆盖），安装后生成 `.installed-version`（version / installed_at / source 三行）。

## 停机条件（任一命中即停）

1. 命中 reserved 清单事项；
2. 授权书预算触顶或过期；
3. 同一任务连续 3 次验收失败；
4. 执行者报告环境类 FATAL（端点不可达、配置缺失等）；
5. 人叫停。

停机时输出：现状摘要 + 已落盘产物清单 + 需要人做的最小动作清单。
